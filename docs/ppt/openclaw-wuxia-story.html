OpenClaw 镖局风云录

一卷关于 AI Agent 的武侠喜剧
"天下武功，唯快不破。
天下 Agent，唯 OpenClaw 镖局最稳。"
——《硅谷江湖快报》头条

话说在硅谷大陆的腹地，有一座镖局叫 OpenClaw。别的镖局押金押银，它押的是——指令与智慧。江湖上但凡有人想让 AI 替自己跑腿干活的，十有八九都来找它。

镖局的主人叫 网关真人（Gateway）。此人长得仙风道骨，长年坐在山门口的太师椅上，眼皮都不抬一下。他不亲自干活，但管着整个镖局的命脉——谁进谁出、谁的令牌有效、谁的签名造假。据说他的绝技叫"千手总机"，能同时调度上百条连接，从不出错。

我们的故事，要从一个叫 林小链（LinkChat）的年轻人说起。

第一章
山门验身

卯时三刻，天刚蒙蒙亮。林小链背着一把长剑，风尘仆仆来到 OpenClaw 镖局门前。

他刚在门前站定，山门上方突然飞出一道金色符文——上面写着一个奇怪的字符串 xK9m2p...，旁边还标注了一个时间戳 1737264000000。

山门符文：来者何人？这是你的随机暗号（nonce）。想进门，就用你的密钥签名后原样奉还。限时一刻钟，过期不候！

林小链吓了一跳。他没想到这镖局的大门还有这种机关——先给你一道暗号，你必须用自己的密钥签名，再原样送回去，证明"我是我"。

他定了定神，从怀里掏出一叠文书——

第一张是身份铭牌：姓名 linkchat-desktop，籍贯 windows，门派 operator。

第二张是权限腰牌：两块小木牌，一块刻着 operator.read（可看），一块刻着 operator.write（可写）。

第三张最重要——祖传密钥。上面有他的公钥、签名、还有一个必须和山门符文一字不差的 nonce。

林小链：（双手递上）前辈，这是我的通关文牒。

山门沉默了三息。

突然，一阵劲风扫过——符文碎裂，大门轰然洞开！

网关真人：（声音从门内传来，中气十足）hello-ok。协议版本 3。以后每 15 秒给本座报一次到，否则当你是逃客，直接断连。进去吧。
WS 握手分三步：Gateway 下发 connect.challenge（含 nonce）→ 客户端签名后发 connect 请求 → Gateway 返回 hello-ok（含 tickIntervalMs: 15000）。

林小链松了口气，抬脚正要迈过门槛——

网关真人：等等。你那 caps 字段写了什么？
林小链：（紧张）回前辈，小生写了 caps: []……空的。
网关真人：（冷哼）想收工具事件？caps 里加上 'tool-events'。不声明就别想看到管家用工具。年轻人，协议字段要仔细看。

林小链赶紧改了文书，重新递上。这次网关真人没再说话，只是轻轻点了点头。

LinkChat 第一次对接时忘了声明 caps: ['tool-events']，导致 Agent 执行 system.run 时客户端收不到工具事件。排了半天才定位到。后来加上，问题秒解。
✦ ✦ ✦
第二章
会客室风波

进了镖局大门，一个面容清秀的小厮领着林小链穿过回廊，来到一间精致的厢房前。

小厮：客官，这是您的 会客室（Session）。房间号是 agent:main:main。您跟管家聊的话，隔壁房间的人听不到，我们镖局讲究 per-channel-peer 隔离。
林小链：不错不错。那这间房我能用多久？
小厮：（为难）这个嘛……镖局有规矩。每天凌晨四点——不管你聊没聊完——所有会客室自动打扫，第二天从零开始。
林小链：（震惊）凌晨四点？！要是昨晚聊到三点半，半小时后房间就被打扫了？
小厮：（点头）是的。不过您也可以加一条 idleMinutes: 120——两小时没人说话就提前打扫。两条规矩，哪个先到听哪个的。

林小链正要进门，身后传来一个苍老但不怒自威的声音。

管房婆：（从走廊尽头走来，手里拿着账本）新客？记好了——你的房间超过 30 天不住人，我直接拆。房间总数超过 500 间，老的先拆。我的规矩不是建议，是 enforce 模式——不废话，直接执行。

林小链缩了缩脖子，赶紧进了房间。

Session 重置：daily + atHour=4，也可配 idleMinutes 先到先触发。Maintenance 用 enforce 模式，过期 Session 不留情面。
✦ ✦ ✦
第三章
管家阿管

会客室里坐着一个人。

他约莫三十来岁，穿着一身灰布长衫，面前摆着一张大书桌。桌上整整齐齐码着七八本书，墙上挂着一只青色信鸽、一只蓝色信鸽、一只金色信鸽。

这就是镖局的 管家阿管（Agent）。

阿管：（抬头，微笑）林公子，久等了。我是你的专属管家。你每发一条消息，我就跑一趟完整的循环——翻档案、请示高人、查工具箱、写回信，六步走完算一轮。
林小链："请示高人"是什么意思？
阿管：（指了指自己的头）我这脑子啊，是空的。真正思考的是我请来的高人——LLM。我叫他们"大脑"。不过您放心，我这有一套流程，保证每次办事又快又好。

阿管开始介绍桌上的书：

阿管：这本 AGENTS.md 是操作手册，告诉我什么该做什么不该做。这本 SOUL.md 是我的性格设定——我本来脾气暴躁，但 SOUL.md 里写了"温和耐心"，所以我现在很温柔。这本 USER.md 是老板你的偏好档案……
林小链：（凑过去看）等等，这本 MEMORY.md 是什么？好厚！
阿管：（眼神亮了）这是我的日记本！纯 Markdown，白纸黑字。每次你进来，我自动翻一遍。上面记着——"公子喜欢简洁回复"、"上次讨论选了方案 B"、"公子的猫叫橘座"……
林小链：（感动）你记得我的猫？
阿管：（骄傲）当然。我还有每日便签——今天和昨天的自动展开，三天前的收进抽屉。要是想找旧笔记，我就用 memory_search，混合向量搜索加关键词搜索，连中文都能查。不过这个检索术要消耗一点真气……
林小链：那这本 BOOTSTRAP.md 呢？
阿管：（摆手）入职培训手册，只有新管家第一次上岗才看。我都背下来了，没用了。
Agent 引导文件每轮注入 context。Memory 是磁盘 Markdown，索引存 SQLite（FTS5 + BM25），支持 CJK trigram 分词。
✦ ✦ ✦
第四章
第一封信与蓝鸽的怪癖

林小链坐定，开口道："阿管，帮我查一下今天镖局的运行状态。"

阿管点点头，从墙上取下那只蓝色信鸽。

阿管：公子稍候。我去请示高人，回信会通过蓝鸽分段送来。

片刻后，蓝鸽扑棱棱飞回来，嘴里叼着一张纸条。

林小链展开一看，上面写着：

镖局今日运行正常，连接数 3，活跃会话 12 个。

又过了几秒，蓝鸽又飞回来。林小链再看——

镖局今日运行正常，连接数 3，活跃会话 12 个。最近一次心跳在 30 秒前。

林小链愣住了："等等，它怎么每次都送整封信？不是只送新增的部分？"

阿管：（无奈）这是蓝鸽的怪脾气。它不送差量，每次都送整封信的最新版。第一封写"镖局正常"，第二封写"镖局正常。心跳30秒前"——你得自己算哪部分是新的。这叫 Delta 编码。

林小链想了想，突然问："那如果高人回信分好几段呢？第一段说完，开始第二段的时候，信的内容会突然变短吧？"

阿管：（竖起大拇指）公子聪慧！正是如此。新段开始时文本会重置。我用的检测方法叫 startsWith——每次新信来了，看它是不是旧信的开头。是的话就追加差量，不是的话就判定为新段，另起一行。
林小链：为什么不用长度比较？简单直接。
阿管：（摇头）长度不可靠。万一新段恰好以旧段开头呢？比如旧信是"关于你的问题"，新段恰好是"关于你的第二个问题"——长度变长了，看着像追加，实际是重置。只有 startsWith 能精确判断"新文本是否是旧文本的延续"。
OpenClaw 流式协议发累积全文（非增量 delta），多段回复时文本重置。客户端用 startsWith 检测：true = 追加，false = 段重置。
✦ ✦ ✦
第五章
飞鸽传书的秘密

信收完了，林小链正要起身，突然注意到墙上那只青色信鸽扑棱了一下翅膀。

林小链：这只青鸽是做什么的？
阿管：这是最重要的那只。蓝鸽送信，金鸽报告工具状态，而青鸽——它告诉我什么时候真正干完了。
林小链：（困惑）蓝鸽送完信不就是干完了吗？
阿管：（严肃）公子，这是新手最容易犯的错。我办事不是一锤子买卖。有时高人回答完一段，我会觉得需要用工具查一下——查完再请高人补充。这中间蓝鸽来来回回好几趟。只有当青鸽带着 phase: "end" 飞回来，才代表整个循环结束。记住了——青鸽 end，才算完。
LinkChat 早期犯过——把蓝鸽最后一封信当完成信号，Agent 还在后台用工具，客户端已显示"已完成"。改监听 lifecycle phase=end 后解决。

林小链若有所思地点点头。

阿管：对了，还有那只金鸽。每次我用工具的时候，金鸽会飞出去告诉你"我要用工具了"、"工具执行中"、"结果出来了"。
林小链：那你用什么工具？
阿管：（从桌下拉出一个箱子，打开）这是我的工具箱。最常用的是 system.run——执行 Shell 命令。相当于我能动手干活，不光是动嘴皮子。
✦ ✦ ✦
第六章
工具箱与练功房

午后，林小链让阿管查一下本地磁盘空间。

阿管打开工具箱，取出 system.run，正要动手——

阿管：公子，这个命令不危险，我直接在正厅（gateway）执行了。

片刻后，金鸽飞回，叼着结果：磁盘已用 67%。

林小链：你能直接在我的电脑上执行命令？那岂不是很危险？
阿管：（正色）问得好。镖局有练功房（Sandbox）——用 Docker 搭的隔离空间。危险的活在里面练，出事不伤正厅。默认走 host: "auto"，有练功房就去练功房，没有就在正厅。
林小链：那我要你执行 rm -rf / 呢？

阿管的脸色瞬间严肃起来。

阿管：公子，这种毁天灭地的招式，我有一套双层审批。第一层是工具策略——查白名单、问安全等级。第二层是宿主审批——就算工具策略放行，宿主层面还能再拦一道。两层都过，才能执行。而且——

阿管顿了顿，压低声音。

阿管：真正危险的操作，我会先问你要不要执行。查询类的我直接干，删东西的——得您点头。

林小链这才放下心来。

Exec 工具有 host 路由（auto/sandbox/gateway/node）、security 策略（deny/allowlist/full）、ask 审批。双层审批：工具配置 + exec-approvals.json。Agent 内置安全确认，LinkChat 因此无需额外 DraftService。
✦ ✦ ✦
第七章
藏经阁的危机

申时，阿管正在处理今天的第 47 个请求。突然，他的脸色变得很难看。

阿管：（按着太阳穴）不好……我脑子要炸了。
林小链：（紧张）怎么了？！
阿管：我的 Context 脑容量是 200,000 token。现在对话历史、引导文件、工具结果加起来已经占了 183,616——快到上限了！再撑下去，下次请高人就没空间放提示词了。

话音未落，门外走进来一个老者——须发皆白，背着一只巨大的竹简箱。

藏经阁主：（自我介绍）老朽是 藏经阁主（Compaction）。脑子快满的时候我来压缩——把旧对话请出去，换成一份精简摘要，给近期对话腾地方。
阿管：（急切）快快快！
藏经阁主：（摆手）别急。压缩之前，先把重要笔记存到你的日记本里。压缩完旧对话就变成摘要了，细节找不回来。

阿管赶紧拿起笔，飞快地在 MEMORY.md 里写了几条笔记——"公子正在做性能优化"、"方案 C 已否决"、"服务器负载 67%"。

写完，藏经阁主双手一推——

一股无形的力量扫过房间。桌上的旧文书纷纷卷起，化作几行摘要。只有最近 20,000 token 的对话保留不动。

藏经阁主：好了。脑容量释放了 60%。顺便，我把你 AGENTS.md 里"Session Startup"和"Red Lines"两章重注入了——这两章丢了可不行。还有，你那些 ticket ID 和服务器地址，我用 identifierPolicy: "strict" 保护了，不会被摘要吞掉。
阿管：（活动脖子）舒服多了。谢谢老先生！
Compaction 默认开启。触发：contextTokens > contextWindow - reserveTokens。压缩前自动 Memory Flush。保留 keepRecentTokens: 20000。关键章节通过 postCompactionSections 重注入。

藏经阁主刚走，一个年轻人又探头进来——穿着清洁工的衣服，手里拿着扫帚。

清洁工：阿管哥，我是 清洁工（Context Pruning），跟藏经阁主不一样。他压缩整个对话，我只收拾工具结果。刚才那个 df -h 的结果已经过了 5 分钟缓存期，我来把它裁一下——头 1500 字保留，尾 1500 字保留，中间用省略号替代。
阿管：等等，你跟藏经阁主有什么区别？
清洁工：（认真地）藏经阁主写磁盘，改的是永久记录；我只在内存里收拾，下次请求时工具结果会重新进来。他整理整个对话，我只收拾工具结果。他脑子快炸时才来，我每隔 5 分钟定时巡逻。
阿管：（恍然）所以你是我日常保洁，他是年终大扫除？
清洁工：（竖拇指）精辟！
✦ ✦ ✦
第八章
高人与替补席

林小链对阿管的"请示高人"很感兴趣，追问道："你请的高人到底是谁？"

阿管从抽屉里抽出一张名单。

阿管：镖局跟好几位高人有合作。MiniMax-M2.7 是主力——推理强，中文好，200K context，价格适中。还有 kimi-k2.5——256K 超大 context，代码特别强。DeepSeek 便宜好用。Claude Opus 最贵但最强。
林小链：那高人要是请假了呢？
阿管：（叹气）还真被我碰上过。有一次 MiniMax 连续返回 429——rate limit，"本座正在忙，稍后再来"。镖局有套 指数退避 策略：第一次请他休息 1 分钟，第二次 5 分钟，第三次 25 分钟，第四次之后一律等 1 小时。
林小链：那这 1 小时里你就干等着？
阿管：（摇头）当然不是。我们有候补名单（fallbacks）。MiniMax 挂了，自动切 DeepSeek。候补名单里排了好几个，按顺序试。只有 rate-limit 类的错误才会触发轮换。如果是参数错误、认证失败——直接报错，不瞎折腾。
林小链：有意思。那 MiniMax 有什么怪脾气吗？
阿管：（苦笑）可多了。首先，他名字大小写敏感——必须写 MiniMax-M2.7，大写 M。写成 minimax-m2.7 他直接不理你。其次，他的 API 端点分国内国外——国际走 api.minimax.io，中国走 api.minimaxi.com。注意，中国的那个多了个字母 i！
林小链：多了一个 i？这也太坑了吧？
阿管：还没完。他推荐用 Anthropic 格式通信（api: "anthropic-messages"），不是 OpenAI 格式。Provider 如果没配好，直接报 "Unknown model" 错误。
MiniMax-M2.7 四个坑：1）模型 ID 大小写敏感（大写 M）；2）Context Window 是 200,000 不是 204,800；3）国内 API api.minimaxi.com 多一个 i；4）推荐 anthropic-messages 格式。
✦ ✦ ✦
第九章
深夜巡夜

子时，万籁俱寂。林小链本来已经去睡了，半夜起来上厕所，路过会客室时——

里面亮着灯。

他推门一看，阿管正坐在桌前，面前摊着一本小册子，眉头紧锁。

林小链：（惊讶）你没睡？
阿管：（抬头）公子，我每晚都要巡夜（Heartbeat）。每 30 分钟一次。我翻开巡逻清单 HEARTBEAT.md，按上面的待办走一圈——检查服务器状态、看看有没有未处理的工单。
林小链：这不是门卫每 15 秒点名那个吧？
阿管：（摇头）完全两回事。门卫点名是传输层保活——"我还活着"。我巡夜是真正的干活——执行完整的 Agent 循环，跟白天办事流程一模一样。有事就报告，没事就……

阿管拿出一张纸条，上面写着两个大字：NO_REPLY。

阿管：默念这个词，投递系统就知道"这轮不用告诉用户"，自动吞掉不外传。不是偷懒，是协议约定。
林小链：（佩服）所以你其实整晚都没睡。
阿管：（微笑）镖局的管家，没有下班这一说。不过我可以配置——lightContext: true 时只带巡逻清单不带完整档案，省脑子。isolatedSession: true 时用新房间巡逻，不继承白天的对话。
Heartbeat（调度型心跳）≠ WS Tick（传输层心跳）。heartbeat.every: "30m"，target 默认 "none"（巡逻但不汇报）。NO_REPLY 被投递层过滤，用户看不到。
✦ ✦ ✦
第十章
分身术的代价

第二天上午，林小链给阿管出了个大难题——

林小链：阿管，我需要你同时做三件事：查服务器日志、分析数据库性能、还要写一份周报摘要。
阿管：（面露难色）公子，我一个房间同一时间只能做一件事——这是镖局的规矩，单 Session 串行。不过……

阿管拔下一根头发，吹了一口气——

三个人影从烟雾中走出。长得跟阿管一模一样，只是个子矮了一截，衣服上写着"分身"二字。

阿管：这是我的分身（Subagent）。我可以用 sessions_spawn 召唤他们。分身甲去查日志，分身乙去分析数据库，分身丙去写摘要。他们可以并行干活。
林小链：那分身能再分出分身吗？
阿管：可以，默认只能嵌套 1 层（分身不能再生分身），配置 maxSpawnDepth: 2 后可以嵌套 2 层。而且分身只配看 AGENTS.md 和 TOOLS.md——没资格翻老板的 USER.md，那是我的特权。

三炷香后，三个分身陆续回来交差。阿管拍了拍手，三个分身化作青烟消散。

阿管：分身可以设 cleanup: "delete"——干完就消失，不留档案。也可以设超时，时间到了自动消散。好用是好用，就是费真气。
✦ ✦ ✦
第十一章
武功秘籍

午后，林小链在镖局后院散步，发现一间藏书阁。推门进去，四面墙都是书架，每本秘籍封面上写着不同名字。

阿管不知什么时候跟了过来。

阿管：这是镖局的技能藏书阁（Skills）。每本秘籍都是一种武功——有的教我生成图片，有的教我操作数据库，有的教我做翻译。
林小链：这些秘籍哪来的？
阿管：好几个地方。工作区自带的优先级最高——skills/ 目录里的秘籍只有我自己能用。然后是项目共享的、个人目录的、OpenClaw 全局的……最后是内置的。优先级从高到低，同名秘籍高优先级的覆盖低的。

林小链随手抽出一本，翻开扉页：

---
name: image-lab
description: Generate or edit images
user-invocable: true
---
（正文：技能详细指令……）

阿管：user-invocable: true 意味着用户可以直接用斜杠命令 /image-lab 调用。如果设成 disable-model-invocation: true，我就不会主动用它——只有你点名我才用。
林小链：（眼睛亮了）那我可以自己写秘籍？
阿管：当然！写个 SKILL.md 放进工作区的 skills/ 目录，重启后我就能学了。不过有前提——扉页上可以写 requires.bins 和 requires.env，声明这个秘籍需要什么前置条件。条件不满足的话，秘籍加载了也用不了。
✦ ✦ ✦
第十二章
热更新与不夜门

傍晚时分，林小链注意到镖局的规矩牌上多了一条新规定。但镖局并没有关门重新开张。

林小链：你改了规矩？不用重新开业吗？
网关真人：（不知何时出现在身后）镖局有 热更新 之术。改 Agent 配置、模型、技能、工具——不用关门，直接生效。但如果改的是本座的端口、认证、TLS——那得闭关重启。默认走 hybrid 模式：安全变更即时生效，关键变更自动重启。
林小链：前辈，有个问题我一直想问——我进门的时候，你说 --auth none 不验令牌。但我看我还是得签名、亮身份、走完整套流程。这叫"不验令牌"？
网关真人：（淡淡一笑）"不验令牌"只是不查你的 auth.token。但你的设备身份（device identity）还是要查——公钥、签名、设备 ID 一个都不能少。不查令牌，不代表不查人。你以为挂个 --auth none 的牌子就能裸奔进门？

林小链挠了挠头，想起第一天差点被拒之门外的窘境，不禁汗颜。

--auth none 不验 auth.token，但仍须发送 device identity（空 token 签名 + 公钥 + 设备 ID）。不发 auth 字段会被直接断连。
