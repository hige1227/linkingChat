OpenClaw 科技入职记

一个 AI 公司的职场喜剧
"我们不是在做聊天机器人。
我们是在打造——数字员工。"
—— OpenClaw 科技 CEO 年会发言

在深圳南山科技园的某栋写字楼里，有一家叫 OpenClaw 的 AI 公司。不造硬件，不做社交——它只做一件事：把 AI 变成能干活的数字员工。

公司前台坐着一位气场一米八的行政总监，大家叫她 关姐（Gateway）。她不写代码，不跑模型，但她管着整栋楼的命脉——谁进谁出、谁的工牌有效、谁的指纹造假。据说她能同时处理上百个访客登记，从不出错。

我们的故事，要从一个叫 林小链（LinkChat）的新入职产品经理说起。

第一天
前台登记

周一早上八点半，林小链背着双肩包，紧张地站在 OpenClaw 科技的大堂里。

他刚走到前台，关姐头也不抬，推过来一个平板——上面显示着一个随机验证码 xK9m2p... 和一个时间戳。

关姐：新来的？这是你的临时验证码（nonce）。用你的员工密钥签名一下，原样返回。超时作废。

林小链赶紧从邮件里翻出入职通知书，上面有他的员工密钥。他手忙脚乱地签了名，递回去。

关姐扫了一眼平板，面无表情地开口：

关姐：身份铭牌——姓名 linkchat-desktop，终端 windows，岗位 operator。权限——read 加 write。签名正确，nonce 匹配。

（啪地盖了个章）hello-ok。协议版本 3。以后每 15 秒刷一次门禁卡，否则当你是脱岗，门禁自动吊销。进去吧。工牌在桌上。

林小链刚要转身——

关姐：等等。你 caps 那栏填了什么？
林小链：（紧张）空的……
关姐：（冷冷地）想看工具执行记录？caps 里加上 tool-events。不加就别想看到。小伙子，入职表要仔细填。

林小链赶紧补上，重新递表。关姐这才让开路。

访客登记 = WS 握手：前台下发 connect.challenge（含 nonce）→ 访客签名后发 connect → 前台返回 hello-ok（含 tickIntervalMs: 15000 门禁刷新间隔）。
— · —
第二天
会议室管理

行政小妹领着林小链来到三楼，推开一间会议室的门。

行政小妹：这是你的专属会议室（Session）。编号 agent:main:main。你跟项目经理的谈话别人听不到，我们公司讲究 per-channel-peer 隔离。
林小链：不错。能用多久？
行政小妹：（为难）公司有规定——每天凌晨四点，所有会议室自动清场重置，白板擦干净，第二天从零开始。
林小链：凌晨四点？！我要是加班到三点半——
行政小妹：半小时后白板就被擦了。不过你也可以申请 idleMinutes: 120——两小时没人开会就提前清场。两条规矩，哪个先到听哪个的。

正说着，一个戴眼镜的中年女人从走廊另一头走来，手里拿着一沓表格。

行政主管王姐：新来的？听好了。你那间会议室超过 30 天不用，我直接回收。全公司超过 500 间会议室不用的，老的我先收。我这个人不讲情面，只走 enforce 模式。

林小链默默把会议记录收好。

会议室 = Session。session.reset.mode="daily" + atHour=4，也可配 idleMinutes 先到先触发。行政主管 = Session Maintenance，enforce 模式不留过期 Session。
— · —
第三天
项目经理阿管

会议室里坐着一个人。

三十出头，格子衫，黑框眼镜，桌上摆着七八个文件夹。墙上贴着三张便利贴——一张绿色、一张蓝色、一张黄色。

这就是林小链的 项目经理阿管（Agent）。

阿管：（握手）小林是吧？我是你专属 PM。你的每一个需求，我都走完整流程——收集需求、查资料、请教专家、调用工具、写文档、归档，六步一个闭环。
林小链："请教专家"？
阿管：（指了指自己脑袋）我这脑子是空的，不装模型。真正思考的是我请的外部顾问——LLM。他们按次收费，我负责协调。放心，我有标准流程。

阿管开始介绍桌上的文件夹：

阿管：这本 AGENTS.md 是公司规章制度，什么能做什么不能做。这本 SOUL.md 是我的性格设定——入职前我脾气很差的，但 HR 在 SOUL.md 里写了"温和耐心"，所以你看我现在多温柔。

（翻开一本厚厚的文件夹）这本 MEMORY.md 是我的工作日志。纯 Markdown 格式，没有数据库。每次开会我都自动翻一遍——上面记着"林总喜欢简洁方案"、"上次选了方案 B"、"林总的猫叫橘座"……
林小链：（惊讶）你记得我的猫？
阿管：（推了推眼镜）当然。我还有每日便签——今天和昨天的放在桌上，三天前的收进抽屉。想找旧笔记就用 memory_search，向量搜索加关键词，连中文都能查。
PM 案头文件 = Agent 引导文件：AGENTS.md（制度）、SOUL.md（性格）、USER.md（用户偏好）、MEMORY.md（工作日志）。Memory 是磁盘 Markdown，索引 SQLite（FTS5 + BM25）。
— · —
第四天
邮件系统的怪规则

林小链提了第一个需求："阿管，帮我查一下今天公司系统运行状态。"

阿管点点头，撕下墙上那张蓝色便利贴。

阿管：稍等，我去问顾问，回复会通过蓝条（邮件系统）分段发过来。

几秒后，蓝条上浮现第一行字：

系统运行正常，连接数 3，活跃会话 12。

又过了几秒，蓝条更新了：

系统运行正常，连接数 3，活跃会话 12。最近一次心跳在 30 秒前。

林小链：等等……你怎么每次都发整封邮件？不是只发新增的部分？
阿管：（摊手）公司的邮件系统就这么设计的。每次都发完整版本——第一封写"系统正常"，第二封写"系统正常。心跳30秒前"。你自己看哪部分是新增的。这叫 Delta 编码。
林小链：（皱眉）那如果顾问分好几段回复呢？
阿管：好问题。新段开始时邮件内容会突然缩短——这叫段重置。我用 startsWith 检测：新邮件是不是旧邮件的开头。是就追加差量，不是就判定为新段，另起一行。
林小链：为什么不直接比长度？
阿管：（认真地）假设旧邮件是"关于你的问题"，新段恰好是"关于你的第二个问题"——长度变长了，看着像追加，但其实是新段。只有 startsWith 能准确判断"新内容是不是旧内容的延续"。
邮件系统 = Event Stream（assistant）。发累积全文，多段回复时文本重置。客户端用 startsWith 做 delta + 段重置检测。
— · —
第五天
绿色便利贴的秘密

邮件收完了，林小链注意到墙上那张绿色便利贴闪了一下。

林小链：那张绿的是什么？
阿管：这是最重要的那张。蓝条发邮件内容，黄条报工具状态，而绿条——它告诉我任务什么时候真正做完了。
林小链：邮件发完了不就是做完了？
阿管：（严肃）小林，这是新人最容易踩的坑。我的工作不是发一封邮件就完事。有时候顾问回复完一段，我觉得需要用工具查个数据——查完再让顾问补充。中间蓝条来来回回好几趟。只有绿条上出现 phase: "end"，才代表整个任务闭环结束。

阿管竖起一根手指：

阿管：记住——绿条 end，才算完。
LinkChat 第一版把蓝条最后一封邮件当完成信号——Agent 还在后台跑工具，前端已显示"已完成"。后来改监听 lifecycle phase=end 才解决。
— · —
第一周
工具箱与审批流

周三下午，林小链让阿管查一下磁盘空间。

阿管从桌底拉出一个工具箱，取出 system.run——一个长得像终端的工具。

阿管：这个不危险，我直接在工位上执行了。

片刻后，黄条闪了——磁盘已用 67%。

林小链：你能直接在我的电脑上跑命令？不危险吗？
阿管：问得好。公司有隔离实验室（Sandbox）——Docker 虚拟环境。危险操作在里面跑，炸了不影响办公区。默认走 host: "auto"，有实验室就去实验室，没有就在工位上跑。
林小链：那我要你跑 rm -rf / 呢？

阿管放下手里的咖啡杯。

阿管：小林，这种操作要走双层审批。第一层是工具策略——查白名单、确认安全等级。第二层是宿主审批——就算工具策略过了，运维那边还能再拦一道。而且，真正危险的操作——我会先问你"要不要执行"。查数据的我直接跑，删东西的——得你签字。

林小链放下心来。

system.run 的安全机制：host 路由（auto/sandbox/gateway/node）、security 策略、ask 审批。双层关卡：工具配置 + exec-approvals.json。Agent 内置安全确认 = LinkChat 无需额外 DraftService。
— · —
第二周
文档过载危机

周五下午，阿管正在处理本周第 47 个需求。突然，他猛地按住了太阳穴。

阿管：不行了……我脑子要炸了。
林小链：怎么了？
阿管：我的工作记忆容量是 200,000 token。现在所有对话记录、规章制度、工具执行结果加起来已经快满了——183,616 了！再塞下去，下次请顾问连提示词都放不进去了。

话音未落，一个背着巨大公文包的中年人推门进来。

行政总监老压：我是文档精简专员（Compaction）。脑子快满的时候我来处理——把旧对话精简成摘要，给近期内容腾空间。
阿管：快快快！
老压：（摆手）别急。精简之前先把重要笔记存到你的工作日志里。精简完旧对话就变成摘要了，细节找不回来。

阿管赶紧拿起笔，在 MEMORY.md 里飞速记录——"小林在做性能优化"、"方案 C 已否决"、"服务器负载 67%"。

写完，老压打开公文包，从里面掏出一支荧光笔——

"唰"的一声。桌上堆积如山的旧文档像被施了魔法，瞬间压缩成几页摘要。只有最近 20,000 token 的记录保留不动。

老压：搞定了，释放了 60% 空间。顺便，你 AGENTS.md 里"Session Startup"和"Red Lines"两个关键章节我给你重新注入了——丢了不行。还有，你那些工单号和服务器地址，我用了 identifierPolicy: "strict" 保护，不会被摘要吞掉。

老压刚出门，一个穿保洁服的年轻人探头进来。

保洁小李：管哥，我是文件清理员（Context Pruning），跟老压不一样。他精简整个对话，我只收拾工具执行结果——就是那些一次性的查询输出。5 分钟过了保质期我就来清理，头尾保留，中间删掉。
阿管：你跟老压什么区别？
小李：他改档案（写磁盘），永久生效；我只在脑子里收拾（内存），下次开会工具结果会重新进来。他管全部对话，我只管工具输出。他是脑子快炸才来，我每隔 5 分钟定时巡逻。
阿管：所以你是日常保洁，他是年度精简？
小李：（竖大拇指）精辟！
— · —
第三周
外部顾问那些事

林小链对阿管口中的"外部顾问"越来越好奇。

阿管：（掏出名片夹）公司跟好几位顾问有合作。马老师（MiniMax-M2.7）是主力——推理强，中文好，200K 上下文，价格适中。还有金老师（kimi-k2.5）——256K 超大上下文，代码特别强。德老师（DeepSeek）便宜好用。克老师（Claude Opus）最贵但最强。
林小链：那顾问要是没空呢？
阿管：（苦笑）还真碰上过。有次马老师连着返回 429——"本人档期满，稍后再来"。公司有套指数退避策略：第一次让他歇 1 分钟，第二次 5 分钟，第三次 25 分钟，第四次之后一律等 1 小时。
林小链：等 1 小时？你就在那干等着？
阿管：当然不是。我们有候补名单（fallbacks）。马老师没空，自动切德老师。名单上排了好几个，按顺序试。不过只有 rate-limit 类的错误才触发换人。参数错误、认证失败——直接报错，不瞎折腾。
林小链：那马老师有什么怪脾气？
阿管：（叹气）可多了。首先他名字大小写敏感——必须叫"MiniMax-M2.7"，大写 M。写成"minimax-m2.7"他不理你。其次，他国内的办公室地址和国际的不一样——国际 api.minimax.io，国内 api.minimaxi.com。注意，国内的多了个字母 i。
林小链：多一个 i？
阿管：对。他还只接受 Anthropic 格式的需求文档（api: "anthropic-messages"），不收 OpenAI 格式的。地址写错或者格式不对，直接报 "Unknown model"。
MiniMax-M2.7 四个坑：1）模型 ID 大小写敏感；2）Context 是 200,000 不是 204,800；3）国内 API 多一个 i；4）要用 anthropic-messages 格式。
— · —
某天深夜
夜班保安

凌晨一点，林小链加完班回公司拿充电器。路过会议室时——灯亮着。

推门一看，阿管还在。面前摊着一本小册子，眉头紧锁。

林小链：（震惊）你还没下班？！
阿管：（抬头）小林，我每晚都要值班巡检（Heartbeat）。每 30 分钟一次。我翻开巡检清单 HEARTBEAT.md，按上面的待办过一遍——查服务器状态、看有没有未处理的工单。
林小链：这不是关姐那个每 15 秒刷门禁卡的吧？
阿管：（摇头）两码事。刷门禁卡是门禁保活——证明"我还在这栋楼里"。我巡检是真正的干活——跑完整的 PM 流程，跟白天一模一样。有情况就报告，没事就——

阿管在一张便签上写了两个字：NO_REPLY。

阿管：写上这个，邮件系统就知道"这轮不用抄送给用户"，自动吞掉。不是偷懒，是公司规定。
林小链：（心疼）所以你根本不下班。
阿管：（微笑）打工人嘛。不过我可以配置——lightContext: true 时只带巡检清单不带全部档案，省脑子。isolatedSession: true 时用新会议室巡检，不继承白天的讨论。
值班巡检 = Heartbeat（调度型），≠ 门禁保活 = WS Tick（传输层）。heartbeat.every: "30m"，NO_REPLY 被邮件系统过滤，用户看不到。
— · —
第四周
实习生来了

周一早会，林小链给阿管出了个大难题。

林小链：阿管，我需要你同时做三件事：查日志、分析数据库、写周报。
阿管：（苦笑）小林，我一个会议室同一时间只能跑一个任务——公司规定，单 Session 串行。不过……

阿管拿起手机发了三条微信。三分钟后，三个背着双肩包的年轻人鱼贯而入。长得跟阿管有七分像，但工牌上写着"实习生"。

阿管：这是我的实习生（Subagent）。通过 sessions_spawn 调来的。小张去查日志，小李去分析数据库，小王去写周报。他们可以并行。
林小链：实习生能再叫实习生吗？
阿管：能，默认只能套 1 层（实习生不能再叫实习生），配置 maxSpawnDepth: 2 后可以套 2 层。而且实习生只配看 AGENTS.md 和 TOOLS.md——USER.md 是我的机密，他们没资格看。

一个小时后，三个实习生交了差。阿管挥挥手，三人收拾东西走人。

阿管：实习生可以设 cleanup: "delete"——干完就销毁工号，不留档案。也可以设超时，到点自动下班。好用是好用，就是费 HR 额度。
— · —
第五周
技能培训

午休时，林小链在公司休息区的书架上发现一排培训教材。每本封面印着不同名字——"图像生成"、"数据分析"、"翻译专家"……

阿管端着咖啡走过来。

阿管：这是公司的技能培训教材库（Skills）。每本教材教我一种新能力。位置有讲究——你工位上的 skills/ 目录里的教材只有我能用；项目组共享的、个人目录的、公司全局的……最后是公司内置的。同名教材，优先级高的覆盖低的。

林小链抽出一本，翻开扉页：

---
name: image-lab
description: Generate or edit images
user-invocable: true
---
（正文：技能详细指令……）

阿管：user-invocable: true 意味着你可以直接用斜杠命令 /image-lab 点名调用。如果设成 disable-model-invocation: true，我就不会主动用它——只有你点名我才上。
林小链：那我可以自己编教材？
阿管：当然！写个 SKILL.md 放进工位上的 skills/ 目录，我下次开会就能学了。不过可以声明前置条件——requires.bins 要求电脑上有特定软件，requires.env 要求有特定环境变量。条件不满足的话，教材学了也用不了。
— · —
月末
热更新与关姐的底线

月末的一天，林小链发现公司的规章制度悄悄更新了一条。但公司没有停业通知，没有全员邮件。

林小链：规章制度改了？不用停业重开？
关姐：（不知何时出现在身后）公司有热更新机制。改 PM 配置、换顾问、调工具——不用停业，直接生效。但如果改的是我这边的门禁系统、认证方式、网络配置——那得关门重配。默认走 hybrid 模式：安全变更即时生效，关键变更自动重启。
林小链：关姐，有个问题一直想问——入职那天你说 --auth none 不验令牌。但我还是得签名、验指纹、走完整套流程。这叫"不验令牌"？
关姐：（淡淡地）"不验令牌"只是不查你的 auth.token。但你的员工身份（device identity）还是要验——密钥、签名、工号一个不能少。不查令牌，不代表不查人。你以为 --auth none 就能裸脸进公司？

林小链想起入职那天差点被拦在门外的窘境，讪讪地笑了笑。

--auth none 不验 auth.token，但仍须发 device identity（空 token 签名 + 公钥 + 工号）。不发 auth 字段会被直接断连。
— · —
月末总结
速查表

月末复盘会上，阿管递给林小链一张打印好的表格。
