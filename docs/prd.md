## 1. 产品概述

### 1.1 一句话定义

> **你的每一句回复，都有贾维斯帮你想过。**

### 1.2 产品本质

LinkingChat 是一个 **AI-native 社交 App**——界面像微信（零学习曲线），但每一次社交互动都有 **贾维斯（Jarvis）** 在背后帮你。

这不是：
- ❌ 一个 AI 工具 app（没人会主动打开 AI app）
- ❌ 另一个 AI 聊天机器人（Character.AI 做的是"和 AI 聊天"）
- ❌ 远程控制工具加聊天（已过时的定位）

这是：
- ✅ 一个真实的社交 app，用于真实的人际对话
- ✅ AI 原生地融入每一次聊天——不是插件，是灵魂
- ✅ 帮助用户和**真实的人**聊得更好、更高效、更有情商

### 1.3 核心定位

| 属性 | 内容 |
|------|------|
| 核心定位 | AI-native 微信 — 界面像微信，灵魂是贾维斯 |
| 目标用户 | 所有人（任何用微信的人） |
| 差异化 | AI 帮你和真实的人更好地聊天（全球唯一） |
| 竞争优势 | 微信不会在核心聊天里加 AI；ChatGPT 没有社交；Character.AI 只和 AI 聊 |

## 2. 目标用户

### 2.1 主要用户画像

**普通社交用户（核心，80%）**

- 年龄：18–45 岁
- 使用场景：每天回复大量消息（朋友、同事、客户、家人）
- 核心痛点：
  - 回消息脑力消耗大，尤其是对领导、客户、暧昧对象
  - 反复措辞、怕说错话、情商压力
  - 手机上打字效率低，一句话想半天
- 期望：有人帮我想好怎么回，我确认就发

**知识工作者（高价值，20%）**

- 年龄：25–40 岁
- 使用场景：工作沟通 + 需要偶尔远程操作电脑
- 核心痛点：IM 和工具之间来回切换，在手机上无法处理电脑任务
- 期望：手机一句话，电脑帮我搞定

### 2.2 非目标用户

- 专业开发者（不是核心用户，但兼容）
- 需要实时语音/视频通话的用户（不做）
- 企业 SaaS 客户（不是 MVP 方向）

## 3. 核心体验愿景

### 3.1 "贾维斯在你聊天里"体验

用户打开 LinkingChat 收到朋友消息的那一刻，输入框下方自动出现一条建议：

> "辛苦了～要不要一起出去吃个饭放松一下？"

用户看了一眼，觉得比自己想的好，点击直接发送。

**这是产品成功的第一标志。**

### 3.2 三大核心交互（Holy Trinity）

```
用户收到消息
    ↓
贾维斯自动建议回复（Whisper）
    ↓
用户采纳 / 说"帮我回复XX"
    ↓
贾维斯生成草稿（Draft & Verify）
    ↓
用户确认发送
```

远程执行是第三条链路：

```
用户对贾维斯说"帮我运行下脚本"
    ↓
Cloud Brain：AgentOrchestrator 解析意图 → 生成 Shell 命令
    ↓
OpenClaw Gateway：下发命令到桌面端
    ↓
Desktop：CommandExecutor 执行，流式输出
    ↓
贾维斯总结结果回传聊天 / 建议下一步（Predictive Actions）
```

### 3.3 体验基线

基础 IM 体验必须达到微信水平。**如果聊天本身比微信差，用户不会为了 AI 留下来。**

### 4.2 耳语建议 (The Whisper) — P0

> **这是 AI-native 社交的灵魂。没有 Whisper，LinkingChat 就是一个普通聊天软件。**

#### 功能描述

用户在任意一对一或群组会话中收到新消息时，贾维斯自动在输入框下方出现建议，无需用户触发任何操作。

#### 触发条件

- 用户收到新消息（非自己发送的消息）
- 用户当前正在该会话页面（非后台）
- 用户未在输入框中正在输入内容
- 距该会话上次 Whisper 建议 ≥10 秒（防抖）
- 用户未关闭 Whisper 功能（可在设置中关闭，默认开启）

#### 建议内容规格

- 1 条最优回复（直接显示在输入框下方）
- 2 条备选回复（可展开查看）
- 基于最近 20 条消息的上下文生成
- LLM Provider：DeepSeek（快速、低延迟）

#### UI 行为

- 建议以淡入动画（200ms fade-in）出现
- 不遮挡消息列表，不弹窗，不打断用户
- 用户可点击建议填入输入框（可继续编辑后发送）
- 用户可点击 ✕ 关闭当前建议（该消息不再建议）
- 用户开始主动输入时，建议自动隐藏

#### 性能要求

- 收到消息 → 建议出现：**≤ 2 秒（P95）**
- 失败时静默降级（不显示建议，不报错）

#### AI 存在感视觉

- 建议出现时，输入框边框显示 AI accent 颜色的微弱光晕
- 建议文本前有贾维斯专属图标

#### 用户故事

```
AS A 用户
WHEN 我收到暧昧对象发来的消息"今天好累啊..."
THEN 输入框下方自动出现贾维斯建议："辛苦了～要不要一起出去吃个饭放松一下？"
AND  我可以直接点击发送，或编辑后发送，或忽略自己打字
```

#### 验收标准

- [ ] 收到消息后 2 秒内出现建议（P95）
- [ ] 建议内容与对话上下文相关（非通用套话）
- [ ] 建议可点击填入输入框
- [ ] 建议可关闭/忽略，关闭后该条消息不再弹出
- [ ] 用户输入时建议自动隐藏
- [ ] 设置中可全局关闭 Whisper
- [ ] 建议失败时静默降级（不显示错误，不影响聊天）
- [ ] Desktop 和 Mobile 均支持

### 4.3 代理草稿 (Draft & Verify) — P0

> **贾维斯帮你想好了怎么说，但你说了算。**

#### 功能描述

用户在与贾维斯（Supervisor Bot）的对话中，用自然语言说明需要代写什么消息，贾维斯生成草稿供用户审核确认后发送。贾维斯永远不会自动发送消息。

#### 触发方式

用户对贾维斯说自然语言请求，如：
- "帮我回复张总，说周五开会没问题"
- "给王总发个消息，问他什么时候方便聊"
- "帮我跟老板请明天的假，理由是家里有事"

贾维斯通过 LLM 意图识别判断是否为"代写草稿"类请求。

#### 草稿生成流程

```
用户消息 → 意图识别（DeepSeek）
    ↓ 判定为 draft 类型
识别目标收件人 + 消息内容意图
    ↓
调用 DraftService 生成得体文案（Kimi，语言质量优先）
    ↓
以 DraftCard 形式展示在贾维斯对话中
```

#### DraftCard UI 规格

- 展示生成的草稿文本
- 显示目标收件人（"发给：张总"）
- 操作按钮：**[编辑]** / **[发送]** / **[取消]**
- [编辑]：草稿文本填入对应会话的输入框，用户可修改后手动发送
- [发送]：草稿直接发送到目标会话（需用户主动点击）
- [取消]：丢弃草稿，无任何操作

#### 草稿内容要求

- 语气得体、高情商，符合中文职场/社交语境
- 保留用户的核心意图，但优化措辞
- LLM Provider：Kimi（复杂文案，语言质量优先）

#### 验收标准

- [ ] "帮我回复张总说周五开会没问题" → DraftCard 出现，内容得体
- [ ] 点击 [发送] → 消息出现在张总的对话中（不是贾维斯的对话）
- [ ] 点击 [编辑] → 草稿填入对应会话输入框
- [ ] 点击 [取消] → 草稿消失，无任何发送
- [ ] 贾维斯不会在用户点击 [发送] 之前自动发送任何消息
- [ ] Desktop 和 Mobile 均支持

### 4.4 预测执行 (Predictive Actions) — P1

#### 功能描述

设备命令执行失败后，贾维斯自动分析错误并建议修复方案，以可点击的行动卡片形式呈现。

#### 触发条件

- 桌面端 Shell 命令执行失败（exit code ≠ 0 或 stderr 非空）
- 或用户对贾维斯说"帮我分析这个错误"并附上错误日志

#### 行动卡片规格

| 风险等级 | 颜色 | 行为 |
|---------|------|------|
| Safe | 绿色 | 可直接点击 [执行] |
| Caution | 黄色 | 点击 [执行] 后显示确认弹窗 |
| Dangerous | 红色 | 无 [执行] 按钮，仅展示信息 |

黑名单命令（`rm -rf /`, `format`, `DROP TABLE` 等）永远不生成执行按钮。

#### 验收标准

- [ ] 命令失败 → 3 秒内出现行动卡片
- [ ] 安全命令：一键执行
- [ ] 危险命令：显示警告，无执行按钮
- [ ] 黑名单命令完全屏蔽，不展示执行选项

### 4.5 远程执行 (Remote Execution) — P1

#### 功能描述

用户通过移动端对贾维斯发出自然语言指令，贾维斯解析意图后在用户的桌面端执行命令，结果回传到聊天窗口。

#### 执行链路

```
Mobile：用户说"帮我运行项目里的测试"
    ↓
Cloud Brain：AgentOrchestrator 解析意图 → 生成 Shell 命令
    ↓
DraftCard 展示命令供用户确认（Draft & Verify 复用）
    ↓  [用户点击执行]
OpenClaw Gateway：下发命令到桌面端
    ↓
Desktop：CommandExecutor 执行，流式输出
    ↓
贾维斯总结结果 → 回传聊天窗口
```

#### 安全规则

- 贾维斯生成命令后必须展示 DraftCard 供用户确认
- 危险命令额外显示确认弹窗
- 所有命令执行日志可查

#### 性能要求

- 命令响应延迟：**≤ 3 秒（P95）**，含网络往返

## 6. AI 行为准则

> **贾维斯是用户的助手，不是用户的代理人。**

以下是 AI 行为的硬性约束，任何功能都不得违反：

### 6.1 草稿即正义（核心原则）

贾维斯**永远不会**自动发送消息。所有 AI 生成的内容，必须经过用户明确点击 [发送] 或 [确认] 后才会触达他人。无例外。

### 6.2 透明度

- 贾维斯生成的内容必须清晰标识为 AI 生成（有 AI 图标/标签）
- 用户始终知道哪些内容来自 AI，哪些来自自己

### 6.3 可拒绝性

- 所有 AI 建议都可以被忽略或关闭
- 用户可在设置中完全关闭 Whisper 功能
- 用户可在任意时刻取消草稿

### 6.4 最小权限

- 贾维斯访问消息内容仅用于生成建议，不用于其他目的
- 远程命令执行必须经过用户确认
- 危险操作（文件删除、系统修改）有额外确认层

### 6.5 降级策略

- AI 服务不可用时，核心 IM 功能不受影响
- Whisper 失败时静默降级（不报错，不影响聊天）
- Draft 生成失败时告知用户，不自动重试

## 7. 设计规范

### 7.1 设计原则

1. **零门槛**：任何会用微信的人都会用 LinkingChat，无需学习
2. **AI 可见但不扰人**：贾维斯随时在场，但不打断用户的自然流程
3. **两端一致**：Mobile 和 Desktop 视觉语言一致，操作逻辑一致
4. **WeChat 基线，AI 上限**：IM 功能对标微信，AI 体验超越任何现有产品

### 7.2 AI 存在感视觉语言

贾维斯的存在必须在视觉上可感知：

| 场景 | 视觉效果 |
|------|---------|
| Whisper 建议出现 | 输入框边框 AI accent 颜色光晕 + 内容 fade-in 200ms |
| 贾维斯思考中 | 呼吸灯动画（区别于普通"输入中"省略号） |
| DraftCard 出现 | slide-up + fade-in 入场动画 300ms |
| 预测行动卡片 | 按钮微弱 pulse 动画（吸引注意力） |
| 贾维斯消息气泡 | 专属 AI 图标 + 轻微渐变背景，区别于普通消息 |

### 7.3 颜色体系


## 8. 成功指标

### 8.1 北极星指标

**Whisper 采纳率 (Whisper Accept Rate)**

- 定义：贾维斯建议被用户实际采纳（点击建议 → 发送）的比例
- 计算：`adopted_whispers / total_whispers_shown`
- 目标：**> 30%**
- 低于 15% 触发告警：建议质量不够，立即优化 prompt 或上下文窗口

### 8.2 功能指标

| 指标 | 定义 | 目标 | 告警阈值 |
|------|------|------|---------|
| Whisper 采纳率 | 建议被采纳的比例 | > 30% | < 15% |
| Draft 发送率 | 草稿被用户确认发送的比例 | > 60% | < 30% |
| Whisper 延迟 P95 | 消息到达 → 建议出现 | < 2s | > 5s |
| 日均 AI 辅助对话数 | 当日有 AI 参与的对话数 | 周环比增长 | 连续 3 天下跌 |

### 8.3 基础 IM 指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 消息发送成功率 | 发送成功 / 发送尝试 | > 99.5% |
| 消息投递延迟 P95 | 发送 → 对方收到 | < 500ms |
| 次日留存率 | 注册第 2 天回来的比例 | > 40% |
| 7 日留存率 | 注册第 7 天回来的比例 | > 20% |

## 10. 范围外 (Out of Scope)

以下功能在 MVP 及 v1.x 中**不做**：

| 功能 | 原因 |
|------|------|
| 语音/视频通话 | WebRTC 工程量巨大；用户会用微信/FaceTime 打电话 |
| 朋友圈/动态流 | 不是核心社交场景；分散贾维斯体验的注意力 |
| 多 Bot（Coding Bot 等） | MVP 只做一个贾维斯做到极致，v1.x 再扩展 |
| Bot 市场/自定义 Bot | v2.0 功能 |
| 企业版/SaaS | 不是 MVP 目标市场 |
| 端到端加密 (E2EE) | 技术复杂度极高，且与 AI 建议功能（需读取上下文）冲突 |
| 私密聊天/阅后即焚 | 与 AI 上下文功能冲突 |

## 11. 术语表

| 术语 | 定义 |
|------|------|
| **贾维斯 (Jarvis)** | LinkingChat 内置的 AI 助手，以 Supervisor Bot 形式存在，固定置顶 |
| **Supervisor Bot** | 用户账号自动创建的系统级 Bot，是贾维斯的实体，不可删除 |
| **Whisper（耳语建议）** | 收到消息后自动出现的 AI 回复建议功能，P0 核心功能 |
| **Draft & Verify（代理草稿）** | 用户告诉贾维斯代写消息，贾维斯生成草稿供用户确认，P0 核心功能 |
| **Predictive Actions（预测执行）** | 命令执行后 AI 预判下一步并生成行动卡片，P1 功能 |
| **DraftCard** | 草稿的 UI 组件，包含草稿内容 + 编辑/发送/取消按钮 |
| **WhisperBar** | Whisper 建议的 UI 组件，显示在输入框下方 |
| **Cloud Brain** | NestJS 服务端，托管所有 LLM 推理和 Agent 逻辑 |
| **Local Hands** | 桌面端，接受 Cloud Brain 指令并执行本地操作 |
| **OpenClaw** | 桌面端远程命令执行的底层组件 |
| **AI accent** | 设计语言中用于标识 AI 存在的专属颜色（紫色系 #9B5DE5） |
| **Whisper Accept Rate** | Whisper 采纳率，产品北极星指标 |
| **Ghost Text** | v1.2 规划功能：输入框灰体自动补全，类似 GitHub Copilot |
| **Holy Trinity** | 三大核心交互的合称：Whisper + Draft & Verify + Predictive Actions |
