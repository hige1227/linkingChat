## 一、OpenClaw Docker 连接调通 (04-02)

### 1.1 Controller 401 修复

**问题**：`GET /openclaw/gateway/connect` 返回 401
**原因**：`openclaw.controller.ts` 读 `req.user.sub`，但 JwtStrategy.validate 返回 `{userId, username}`
**修复**：改为 `req.user?.userId || req.user?.sub`

- [x] 修复后 API 返回 200 + gateway URL/token

### 1.2 Docker 端口转发失败

**问题**：`curl http://127.0.0.1:18790/health` 返回空响应
**原因**：Gateway 默认 `--bind loopback`，绑 127.0.0.1 在容器内，Docker NAT 转发到不了
**修复**：
1. `docker-compose.yaml` 加 `command: --bind lan`
2. `openclaw config set gateway.controlUi.dangerouslyAllowHostHeaderOriginFallback true`
3. Volume 持久化 config (`openclaw_data:/home/node/.openclaw`)

- [x] `curl health` 返回 `{"ok":true,"status":"live"}`
- [x] Gateway 日志显示 `listening on ws://0.0.0.0:18789`

### 1.3 openclaw-node 设备签名被拒 (1008)

**问题**：`openclaw-node@0.3.0` 的 `buildSignedDevice` 签名被 Gateway 拒绝 (WebSocket close code 1008)
**临时方案**：`(client as any).deviceIdentity = null` 跳过签名
**后果**：连接成功但缺少 `operator.write` scope，命令执行降级到 child_process

- [x] 连接成功，Desktop sidebar 双绿 (WS + AI Agent)
- [x] 命令执行通过 child_process 降级成功

## 四、本地进程模式切换 (04-05)

### 4.1 为什么切到本地

Docker 容器中的命令执行在**容器内**（Linux），不在用户电脑上。本地模式才是正确的生产路径。

### 4.2 本地 OpenClaw 安装

```bash
pnpm add -w openclaw  # 项目本地安装，v2026.4.2
```

- [x] `npx openclaw --version` → `OpenClaw 2026.4.2`
- [x] 模型配置：`npx openclaw models set kimi-coding/k2p5`
- [x] API key：`npx openclaw models auth paste-token --provider kimi-coding`

### 4.3 进程 spawn

**修复**：
1. `node_modules/.bin/openclaw` 是 shell 脚本，Windows 不能 `node` 跑 → 改用 `require.resolve('openclaw')` 找 `openclaw.mjs`
2. 缺少 `--allow-unconfigured` flag → 加上
3. URL 从 `http://` 改为 `ws://`

- [x] Gateway 本地 spawn 成功，PID 正常
- [x] `agent model: kimi/k2p5` 加载
- [x] `listening on ws://127.0.0.1:18789`
- [x] WS 连接 hello-ok 成功 (`Connected to Gateway successfully (v2026.4.2)`)

### 4.4 当前限制

- Device pairing 仍然阻塞 `operator.write` scope
- 无 device identity → 连接成功但 scope 不够 → Agent 命令被拒
- 有 device identity → Gateway 要求 pairing → 静默超时（不回复错误）
- **临时方案**：命令走 child_process 降级（46ms，可用）
