## 问题 1：Prisma Client 生成 EPERM 错误

**阶段**：数据库迁移（`prisma db push`）

**现象**：
```
EPERM: operation not permitted, rename 'query_engine-windows.dll.node.tmp' -> 'query_engine-windows.dll.node'
```

**原因**：Windows 文件锁定 — 有 Node.js 进程正在使用 Prisma 引擎 DLL，导致无法覆盖写入。

**修复**：
1. 手动删除被锁定的 DLL 文件：`rm -f node_modules/.pnpm/@prisma+client@.../query_engine-windows.dll.node`
2. 重新运行 `npx prisma generate` 成功

**文件**：无代码变更

## 问题 2：search_vector 列被 db push 误删

**阶段**：数据库迁移

**现象**：`npx prisma db push --accept-data-loss` 同步 `isEmailVerified` 字段时，顺带删除了 `messages` 表的 `search_vector` tsvector 列（118 条非空值丢失）。

**原因**：`search_vector` 列是通过 raw SQL migration 添加的（`20260307120000_add_message_search_vector`），未声明在 `schema.prisma` 中。`db push` 以 schema.prisma 为准，删除了它认为"多余"的列。

**修复**：通过 `prisma db execute` 重新执行 raw SQL 恢复列、索引、触发器和回填数据：
```sql
ALTER TABLE "messages" ADD COLUMN IF NOT EXISTS "search_vector" tsvector;
CREATE INDEX IF NOT EXISTS "idx_messages_search" ON "messages" USING GIN("search_vector");
CREATE OR REPLACE FUNCTION messages_search_trigger() RETURNS trigger AS $$ ... $$;
CREATE TRIGGER messages_search_update BEFORE INSERT OR UPDATE OF "content" ON "messages" ...;
UPDATE "messages" SET "search_vector" = to_tsvector('simple', COALESCE("content", ''));
```

**后续**：为 `isEmailVerified` 补建了正式 migration 文件 `20260307150000_add_email_verified`，避免以后再次出现同类问题。

**文件**：`apps/server/prisma/migrations/20260307150000_add_email_verified/migration.sql`（新建）

## 问题 3：Server 端口被占用 (EADDRINUSE :3008)

**阶段**：启动服务端（`pnpm dev:server`）

**现象**：
```
Error: listen EADDRINUSE: address already in use :::3008
```

**原因**：之前的 Node 进程未正常退出，仍占用 3008 端口。

**修复**：通过 `netstat -ano | findstr ":3008"` 找到占用进程 PID，`taskkill /F /PID <pid>` 终止后重启。

**文件**：无代码变更

## 问题 4：Desktop 浏览器模式 window.electronAPI 未定义

**阶段**：启动桌面客户端（`pnpm dev:desktop`），通过浏览器 `http://localhost:5174` 访问

**现象**：
```
TypeError: Cannot read properties of undefined (reading 'getToken')
    at App.tsx:36
```
页面空白，React 崩溃。

**原因**：`App.tsx` 的 `useEffect` 直接调用 `window.electronAPI.getToken()`，但浏览器环境下没有 Electron preload 脚本，`window.electronAPI` 为 `undefined`。

**修复**：添加 `window.electronAPI` 存在性检查：
```tsx
useEffect(() => {
  if (window.electronAPI) {
    window.electronAPI.getToken().then((token) => { ... });
  } else {
    setChecking(false); // 浏览器 dev 模式直接跳到登录页
  }
}, []);
```

**文件**：`apps/desktop/src/renderer/App.tsx`

## 问题 6：Electron 启动时 OpenClaw 连接失败弹出错误对话框

**阶段**：启动桌面客户端

**现象**：Electron 窗口弹出系统级错误对话框，显示 WebSocket 连接失败。用户必须手动关闭对话框才能继续使用。

**原因**：`openclaw-node` 包内部 WebSocket 连接失败时抛出未捕获的异常（uncaughtException / unhandledRejection），Electron 默认行为是弹出错误对话框。

**修复**：在主进程入口 `index.ts` 添加全局异常处理器 + `connectToGateway()` 调用添加 `.catch()`：
```ts
process.on('uncaughtException', (err) => {
  console.error('[Main] Uncaught exception:', err.message);
});
process.on('unhandledRejection', (reason) => {
  console.error('[Main] Unhandled rejection:', reason);
});
```

**文件**：`apps/desktop/src/main/index.ts`

## 问题 7：Zustand selector 无限循环导致 Electron 白屏

**阶段**：启动桌面客户端（Electron 窗口内）

**现象**：
```
The result of getSnapshot should be cached to avoid an infinite loop
Uncaught Error: Maximum update depth exceeded.
```
Electron 窗口完全空白（React 崩溃）。浏览器模式正常（因为走的是登录页，不触发该代码路径）。

**原因**：`ChatPage.tsx` 中 Zustand selector 返回 `[]` 字面量：
```tsx
const drafts = useAiStore((s) => s.drafts[converseId] ?? []);
```
每次 render 时 `[]` 都是新对象引用（`[] !== []`），Zustand 认为状态变化 → 触发重渲染 → 又返回新 `[]` → 无限循环。

**修复**：将空数组提取为模块级常量，保证引用稳定：
```tsx
const EMPTY_DRAFTS: DraftItem[] = [];
const EMPTY_PREDICTIONS: PredictiveSuggestion[] = [];

const drafts = useAiStore((s) => s.drafts[converseId] ?? EMPTY_DRAFTS);
const predictions = useAiStore((s) => s.predictions[converseId] ?? EMPTY_PREDICTIONS);
```

**文件**：`apps/desktop/src/renderer/pages/ChatPage.tsx`

## 问题 9：useChatSocket 多实例创建多个 WebSocket 连接

**发现方式**：Code Review Agent

**严重程度**：严重

**现象**：`useChatSocket()` hook 在 `MainLayout`、`WhisperBar`、`DraftCard`、`PredictiveActionCard` 4 个组件中分别调用。每次调用都会创建一个新的 Socket.IO 连接。如果界面上有 3 个 DraftCard + 2 个 PredictiveActionCard，就会同时建立 **7 个 WebSocket 连接**。

**影响**：
- 消息重复处理（同一条消息被 7 个 handler 各处理一次）
- 服务器资源浪费
- 竞态条件

**修复**：将 `useChatSocket.ts` 改为 **模块级单例模式**：
- 连接逻辑提取到 `initSocket()` 函数，通过 `connectionInitiated` 标志确保只执行一次
- Socket 存储在模块级 `sharedSocket` 变量，所有组件共享
- 连接状态通过 `connectedListeners` Set 广播给所有订阅的组件
- emit helpers 直接使用 `sharedSocket`

**文件**：`apps/desktop/src/renderer/hooks/useChatSocket.ts`（重写）

## 问题 10：ProfilePage logout 未调用 electronAPI.logout()

**发现方式**：Code Review Agent

**严重程度**：严重

**现象**：ProfilePage 的登出按钮只清除 `localStorage` 并刷新页面，没有调用 `window.electronAPI.logout()`。

**影响**：
- JWT token 留在 Electron 主进程的 `AuthStore` 中
- 下次启动 app 时会自动使用旧 token 登录
- 登出功能实际无效

**修复**：在 `handleLogout` 中添加 `await window.electronAPI.logout()` 调用。

**文件**：`apps/desktop/src/renderer/pages/profile/ProfilePage.tsx`

## 问题 11：App.tsx getToken() 缺少 .catch() 处理

**发现方式**：Code Review Agent

**严重程度**：中

**现象**：`window.electronAPI.getToken().then(...)` 没有 `.catch()`。如果 IPC 通信失败，`checking` 状态永远为 `true`，App 返回 `null`，用户看到永久白屏。

**修复**：添加 `.catch(() => setChecking(false))`，确保失败时也能进入登录页。

**文件**：`apps/desktop/src/renderer/App.tsx`

## 问题 12：VoiceMessage audio.play() 未捕获 Promise rejection

**发现方式**：Code Review Agent

**严重程度**：中

**现象**：`audio.play()` 返回 Promise，可能因 autoplay 策略或音源加载失败而 reject。未捕获会导致 `isPlaying` 状态错误（显示"暂停"按钮但实际没在播放）。

**修复**：添加 `.catch(() => setIsPlaying(false))`。
