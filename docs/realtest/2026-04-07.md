## 二、自动化测试

### 2.1 ws-protocol 类型兼容 (validator-compat.spec.ts)

**问题**：Zod schema 中 `avatarUrl` 用了 `.nullable().optional()`，但 TypeScript 接口只有 `optional`（不含 `null`），导致 `AssertAssignable` 编译失败。同样问题出现在 `metadata`、`replyToId`、`deletedAt`。

**修复**：在 `packages/ws-protocol/src/payloads/chat.payloads.ts` 中将相关字段类型加上 `| null`：
- `MessageResponse.author.avatarUrl` → `string | null`
- `MessageResponse.metadata` → `Record<string, unknown> | null`
- `MessageResponse.replyToId` → `string | null`
- `MessageResponse.deletedAt` → `string | null`
- `ConverseResponse.members[].avatarUrl` → `string | null`
- `GroupCreatedPayload.members[].avatarUrl` → `string | null`
- `GroupMemberAddedPayload.members[].avatarUrl` → `string | null`

**结果**：34 suites / 396 tests 全部通过

## 三、链路 A：Desktop Bot DM → OpenClaw 流式回复

### 3.1 无限重渲染 (ChatThread.tsx)

**问题**：打开 Bot 聊天窗口后浏览器崩溃，控制台报 "Maximum update depth exceeded"

**原因**：Zustand selector 内 `Object.values(s.streamingMessages).filter(...)` 每次调用都返回新数组引用，`useSyncExternalStore` 判定 state 变了 → 重渲染 → 又拿到新引用 → 无限循环

**修复**：selector 只取 `streamingMessages` map 对象（引用稳定），用 `useMemo` 在组件内做 filter
```tsx
const streamingMessagesMap = useChatStore((s) => s.streamingMessages);
const streamingMessages = useMemo(
  () => Object.values(streamingMessagesMap).filter((sm) => sm.converseId === converseId),
  [streamingMessagesMap, converseId],
);
```

### 3.2 双重回复 — 两个 AI 管道同时响应

**问题**：发消息给 Bot 后收到两条回复，一条来自 MiniMax-M2 (OpenClaw)，一条来自 DeepSeek (Server SupervisorAgent)

**原因**：`MessageInput` 在 Bot 聊天时既通过 REST 持久化消息（触发 Server 端 `detectBotRecipient` → SupervisorAgent），又通过 OpenClaw 流式发送（本地 Agent 回复）

**修复**：
- `CreateMessageDto` 增加 `skipBotDispatch` 字段
- Desktop Bot 消息持久化时传 `skipBotDispatch: true`
- `MessagesService.create` 检查此 flag 跳过 `detectBotRecipient`

### 3.3 流式回复文本重复 / 结巴

**问题**：Bot 回复内容大量重复，如同一句话出现 2-3 次

**根因 1 — IPC 监听器泄漏**：`preload/index.ts` 中 `onOpenClawStreamChunk` 用匿名函数 `(_event, data) => callback(data)` 包装 callback 注册到 ipcRenderer，但 `offOpenClawStreamChunk` 试图移除原始 callback（不同函数引用），监听器永远无法移除。每次组件重挂载叠加一个新监听器。

**修复**：`onOpenClawStreamChunk` 返回 cleanup 函数（闭包中持有包装引用），移除 `offOpenClawStreamChunk` API：
```typescript
onOpenClawStreamChunk: (callback) => {
  const wrapped = (_event, data) => callback(data);
  ipcRenderer.on('openclaw:stream-chunk', wrapped);
  return () => ipcRenderer.removeListener('openclaw:stream-chunk', wrapped);
},
```

**根因 2 — Delta 编码与累积文本**：`openclaw-ws-client.ts` 的 delta 编码假设 Gateway 始终发累积全文，但多段回复（assistant → tool → assistant）时累积文本会重置。

**修复**：加段重置检测——新 chunk 若不以 `lastText` 开头则视为新段，输出完整文本并重置：
```typescript
if (chunk.text.startsWith(lastText)) {
  const delta = chunk.text.slice(lastText.length);
  lastText = chunk.text;
  if (delta) yield { type: 'text', text: delta };
} else {
  lastText = chunk.text;
  if (chunk.text) yield { type: 'text', text: chunk.text };
}
```

### 3.4 结果

- [x] Bot DM 发消息 → 流式打字效果显示 → 完成后消息持久化
- [x] 刷新页面消息仍在
- [x] 只有一条回复（OpenClaw / MiniMax-M2）

## 五、链路 C：群聊 @ai → Supervisor 回复

### 5.1 @ai 被 Desktop 拦截为 Whisper

**问题**：群聊中输入 `@ai` 后消息被 Desktop 端拦截，显示 Whisper 建议条，消息未发送到服务器

**原因**：`MessageInput` 的 `showAiHint` 拦截逻辑不区分群聊/私聊

**修复**：`if (showAiHint)` → `if (showAiHint && !isGroup)`，群聊中 `@ai` 正常发送到服务器

### 5.2 Supervisor Bot 无法在群聊发消息

**问题**：消息发到服务器后，`MentionService.routeToSupervisor` 正确派发到 SupervisorAgent，但 Agent 调用 `messagesService.create` 时因 `verifyMembership` 失败（Bot 不是群成员）

**修复**：`messagesService.create` 增加可选 `options` 参数：
```typescript
async create(userId: string, dto: CreateMessageDto, options?: { skipMembershipCheck?: boolean })
```
SupervisorAgent 调用时传 `{ skipMembershipCheck: true }`。该参数不在 DTO 中，外部 REST 请求无法利用。

### 5.3 Supervisor 回复缺少对话上下文

**问题**：`@ai 总结上述对话，20字` 回复 "对话总结：用户要求20字内总结对话内容"，AI 只看到了 @ai 消息本身

**修复**：`SupervisorAgent.handleUserMessage` 在调 LLM 前从数据库获取最近 20 条消息作为上下文，去掉 `@ai` 前缀后拼入 prompt

### 5.4 结果

- [x] 群聊 `@ai xxx` → 消息正常发出 → Supervisor Bot 在群里回复
- [x] 回复内容包含对话上下文理解
- [x] 使用 DeepSeek 模型（Server 端 LLM Router）

## 六、统一 @ai 行为

### 6.1 问题

原设计中 `@ai` 在群聊和私聊行为不一致：
- 群聊：发消息 → Bot 回复（正确）
- 私聊：拦截消息 → Whisper 建议（用户体验不一致）

### 6.2 决策

统一 `@ai` = 发消息 + Bot 回复（所有会话类型），Whisper 建议由右侧星号按钮独立触发。

### 6.3 改动

| 文件 | 改动 |

| `MessageInput.tsx` | 移除 `showAiHint` 状态、提示条、`@ai` 拦截逻辑 |

| `mentions.module.ts` | 移除 `AiModule` 导入（不再依赖 WhisperService） |
| `messages.service.ts` | `handleGroupMentions` → `handleMentions`，移除 GROUP 限制；删除旧 whisper 兜底 |
| 测试文件 | 更新 mentions / messages spec，移除 WhisperService mock |

## 十、OpenClaw 工具执行验证

### 10.1 查询类操作

**测试**：在 Supervisor Bot DM 中发送"列出桌面文件"

**结果**：Agent 自主调用 `system.run` 执行 `dir` 命令，返回格式化的文件列表（文件夹/文件分类，markdown 渲染）。用户无需任何额外配置。

- [x] OpenClaw Agent 自主调用工具 ✅
- [x] 工具结果以 markdown 格式展示 ✅

### 10.2 危险操作安全确认

**测试**：发送"帮我删除temp这个文件夹"

**结果**：Agent **没有直接执行删除**，而是回复："删除文件夹是永久性的，操作之前确认一下：你要删除的是桌面上的 temp 文件夹，里头有东西吗？确认的话我就动手，不确定的话先看看里面有啥？"

**结论**：LLM Agent 内置了安全意识，危险操作会先向用户确认。

### 10.3 DraftService / PredictiveService 搁置决策

**背景**：Server 端已实现 `DraftService`（草稿审批状态机）和 `PredictiveService`（危险命令检测 + 操作卡片），原计划用于命令执行的安全层。

**决策**：**暂时搁置，不接入 OpenClaw 链路**。理由：
1. OpenClaw Agent 自身已具备安全确认能力（危险操作先问用户）
2. Bot DM 链路无需额外审批层
3. 这两个服务更适合未来 Server 端链路（群聊 @ai → SupervisorAgent → DeepSeek，没有 OpenClaw 保护时）
4. 等核心功能更完善、有明确需求时再接入
