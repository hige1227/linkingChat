### 问题 1：Desktop Edit 保存后内容回退

**阶段**：Desktop 端 Draft Edit 测试

**现象**：点击 Edit → 修改内容 → Save & Approve → 卡片显示 Approved，但内容恢复为修改前的原文。

**原因**：`DraftCard.tsx` 中 `handleSaveEdit` 只调用 `updateDraftStatus(draftId, 'approved')`，没有将编辑后的内容传递给 store。

**修复**：
1. `aiStore.ts` — `updateDraftStatus` 新增可选参数 `updatedContent`：
```typescript
updateDraftStatus: (draftId, status, updatedContent?) =>
  set((state) => {
    // ...map drafts, 匹配时同时更新 draftContent
    d.draftId === draftId
      ? { ...d, status, ...(updatedContent ? { draftContent: updatedContent } : {}) }
      : d
  }),
```

2. `DraftCard.tsx` — `handleSaveEdit` 传递更新后的内容：
```typescript
const handleSaveEdit = () => {
  const updatedContent = { ...draft.draftContent, content: editText };
  emitDraftEdit(draft.draftId, updatedContent);
  updateDraftStatus(draft.draftId, 'approved', updatedContent);
  setEditing(false);
};
```

**文件**：
- `apps/desktop/src/renderer/stores/aiStore.ts`
- `apps/desktop/src/renderer/components/chat/DraftCard.tsx`

**验证**：✅ Edit 后内容保留

### 问题 2：Desktop 倒计时在 Approve/Reject 后继续

**阶段**：Desktop 端 Draft 状态变化测试

**现象**：点击 Approve 或 Reject 后，状态标签变化了，但倒计时仍在继续倒数。

**原因**：`DraftCard.tsx` 的 timer useEffect 没有检查 `isPending` 状态，即使 draft 已经不是 pending 也继续 countdown。

**修复**：Timer useEffect 在非 pending 状态时立即清除：
```typescript
useEffect(() => {
  if (!isPending) {
    setRemaining('');
    if (timerRef.current) clearInterval(timerRef.current);
    return;
  }
  // ... countdown logic only for pending
}, [draft.expiresAt, draft.draftId, isPending, updateDraftStatus]);
```

**文件**：`apps/desktop/src/renderer/components/chat/DraftCard.tsx`

**验证**：✅ 倒计时在状态变更后停止并消失

### 问题 3：Desktop Approved 状态视觉区分不明显

**阶段**：Desktop 端 Draft 状态测试

**现象**：Approved 后卡片显示绿色标签，但背景没有变化，视觉上不够明显。

**修复**：添加状态背景色：
```typescript
const statusBg = draft.status === 'approved'
  ? 'rgba(76, 175, 80, 0.10)'    // 绿色淡底
  : draft.status === 'rejected'
    ? 'rgba(96, 123, 150, 0.08)'  // 灰色淡底
    : draft.status === 'expired'
      ? 'rgba(96, 123, 150, 0.08)'
      : undefined;
```

**文件**：`apps/desktop/src/renderer/components/chat/DraftCard.tsx`

**验证**：✅ Approved 绿色底、Rejected/Expired 灰色底

### 问题 4：Mobile Draft 卡片 Approve 后消失

**阶段**：Mobile 端 Draft Approve 测试

**现象**：点击 Approve 后卡片直接消失，无法看到 Approved 状态。

**原因**：`chat_thread_page.dart` 使用 `draftState.activeDrafts` 渲染，该 getter 过滤只保留 `DraftStatus.pending`，非 pending 的 draft 被排除。

**修复**：改用 `draftState.drafts` 显示所有状态的卡片：
```dart
// Before
...draftState.activeDrafts.map((draft) => DraftCard(...))

// After
...(List.of(draftState.drafts)..sort((a, b) => a.createdAt.compareTo(b.createdAt))).map((draft) => DraftCard(...))
```

**文件**：`apps/mobile/lib/features/chat/pages/chat_thread_page.dart`

**验证**：✅ 卡片保留并显示 Approved/Rejected/Expired 状态

### 问题 5：Draft 卡片排序错误（新卡片在上）

**阶段**：双端 Draft 排序测试

**现象**：触发 Supervisor (先) 和 Coding Bot (后) 两个 draft，Coding Bot（后触发）反而出现在上方。双端都存在此问题。

**原因**：
1. 两端 store 的 `addDraft` 都用 prepend（新的在前）
2. 渲染层没有按 `createdAt` 排序

**修复**（两步）：
1. Store 中 `addDraft` 改为 append：
```typescript
// Desktop aiStore.ts
[converseId]: [...(state.drafts[converseId] ?? []), draft]  // 原来是 [draft, ...]
```
```dart
// Mobile draft_provider.dart
state = state.copyWith(drafts: [...state.drafts, draft]);  // 原来是 [draft, ...state.drafts]
```

2. 渲染层按 `createdAt` 显式排序：
```typescript
// Desktop ChatPage.tsx
[...drafts].sort((a, b) => new Date(a.createdAt).getTime() - new Date(b.createdAt).getTime())
```
```dart
// Mobile chat_thread_page.dart
(List.of(draftState.drafts)..sort((a, b) => a.createdAt.compareTo(b.createdAt)))
```

**文件**：
- `apps/desktop/src/renderer/stores/aiStore.ts`
- `apps/desktop/src/renderer/pages/ChatPage.tsx`
- `apps/mobile/lib/features/chat/providers/draft_provider.dart`
- `apps/mobile/lib/features/chat/pages/chat_thread_page.dart`

**验证**：✅ 双端排序正确（旧卡片在上，新卡片在下）

### 问题 6：Mobile Edit 保存后内容回退

**阶段**：Mobile 端 Draft Edit 测试

**现象**：与 Desktop 问题 1 相同，Edit → Save & Approve 后内容恢复为原文。

**原因**：`draft_provider.dart` 的 `editAndApprove` 只调用 `_updateDraftStatus` 更新 status，没有更新 `draftContent`。`DraftItem.copyWith` 也不支持 `draftContent` 参数。

**修复**：
1. `DraftItem.copyWith` 新增 `draftContent` 参数：
```dart
DraftItem copyWith({DraftStatus? status, Map<String, dynamic>? draftContent}) {
  return DraftItem(
    // ...
    draftContent: draftContent ?? this.draftContent,
    status: status ?? this.status,
  );
}
```

2. `editAndApprove` 同时更新 content 和 status：
```dart
void editAndApprove(String draftId, Map<String, dynamic> editedContent) {
  _chatSocket.emitDraftEdit(draftId, editedContent);
  state = state.copyWith(
    drafts: state.drafts.map((d) {
      if (d.draftId == draftId) {
        return d.copyWith(status: DraftStatus.approved, draftContent: editedContent);
      }
      return d;
    }).toList(),
  );
}
```

**文件**：`apps/mobile/lib/features/chat/providers/draft_provider.dart`

**验证**：✅ Edit 后内容保留

### 问题 7：Draft 卡片堆积导致 Mobile Column 溢出

**阶段**：Mobile 端多次 Draft 测试

**现象**：多次测试后旧卡片（Approved/Rejected/Expired）累积，Column 超出屏幕高度，Flutter 显示黄黑条纹溢出警告，底部按钮被截断无法点击。

**修复**：非 pending 状态的 Draft 卡片 30 秒后自动从列表中移除。

**Mobile** (`draft_provider.dart`):
```dart
void _scheduleRemoval(String draftId) {
  Future.delayed(const Duration(seconds: 30), () {
    if (!mounted) return;
    state = state.copyWith(
      drafts: state.drafts.where((d) => d.draftId != draftId).toList(),
    );
  });
}
```
在 `approve`、`reject`、`editAndApprove`、`_onDraftExpired` 中调用 `_scheduleRemoval`。

**Desktop** (`aiStore.ts`):
```typescript
removeDraft: (draftId) =>
  set((state) => {
    const newDrafts = {};
    for (const [cid, items] of Object.entries(state.drafts)) {
      newDrafts[cid] = items.filter((d) => d.draftId !== draftId);
    }
    return { drafts: newDrafts };
  }),
```
在 `updateDraftStatus` 和 `expireDraft` 中 `setTimeout(() => removeDraft(draftId), 30_000)`。

**文件**：
- `apps/mobile/lib/features/chat/providers/draft_provider.dart`
- `apps/desktop/src/renderer/stores/aiStore.ts`

**验证**：✅ 卡片状态变更后保留 30 秒供查看，然后自动消失
