## 问题 1：Desktop AI 按钮和 @ai 发送均无反应

**阶段**：手动测试 — Desktop 端 Whisper AI 建议

**现象**：
1. Desktop 端点击 AI ✨ 按钮后 spinner 转 5 秒然后恢复，但没有 Whisper 建议出现
2. 输入 `@ai` 触发提示条后按发送，同样没有建议出现
3. 实时 `@ai` 检测正常工作（输入 `@ai` 提示条出现，删除后消失）
4. F12 Console 日志：

```
[AI] emitWhisperRequest, socket connected: false converseId: cmmiv539c000lgdz8rv0ut8xd
[AI] 5s timeout — loading reset
```

**原因**：两个问题叠加：

1. **WebSocket 断连**：`sharedSocket?.connected` 为 `false`，emit 因 optional chaining `?.` 静默跳过，请求从未发送到服务端。由于普通消息通过 HTTP POST 发送（不依赖 WS），用户感知不到 WS 已断连。断连时没有任何日志输出（`disconnect` 和 `connect_error` handler 缺少 `console.log`），问题完全隐蔽。

2. **onClick handler 传入 MouseEvent**：
```tsx
// Bug: 直接传函数引用，React 将 MouseEvent 作为第一个参数传入
onClick={handleAiRequest}

// handleAiRequest 签名
const handleAiRequest = (userPrompt?: string) => { ... }
```
`handleAiRequest(MouseEvent)` → `emitWhisperRequest(converseId, MouseEvent)` → 服务端收到序列化的 MouseEvent 作为 prompt 字段，即使 socket 连通也会产生错误结果。

**修复**：

1. **Socket 断连自动重连**：`emitWhisperRequest` 检测到 socket 断连时，调用 `sharedSocket.connect()` 发起重连，注册一次性 `connect` 监听器在重连成功后重试请求（3 秒超时放弃）：
```typescript
emitWhisperRequest: (converseId, prompt) => {
  const payload = { converseId, ...(prompt ? { prompt } : {}) };
  if (sharedSocket?.connected) {
    sharedSocket.emit('ai:whisper:request', payload, ...);
  } else if (sharedSocket) {
    console.log('[AI] Socket disconnected, reconnecting...');
    sharedSocket.connect();
    const onReconnect = () => {
      sharedSocket?.emit('ai:whisper:request', payload, ...);
    };
    sharedSocket.once('connect', onReconnect);
    setTimeout(() => { sharedSocket?.off('connect', onReconnect); }, 3000);
  }
},
```

2. **增加连接状态日志**：`connect`、`disconnect`、`connect_error` 事件全部添加 `console.log`，方便排查：
```typescript
socket.on('connect', () => {
  console.log('[ChatSocket] Connected, socket.id:', socket.id);
  ...
});
socket.on('disconnect', (reason) => {
  console.log('[ChatSocket] Disconnected, reason:', reason);
  ...
});
socket.on('connect_error', async (err) => {
  console.error('[ChatSocket] Connect error:', err.message);
  ...
});
```

3. **修复 onClick handler**：用箭头函数包装，同时提取输入框文本作为 prompt：
```tsx
// Before (bug)
onClick={handleAiRequest}

// After (fix)
onClick={() => {
  const inputText = text.trim();
  const prompt = inputText ? inputText.replace(AI_MENTION_RE, '').trim() || undefined : undefined;
  handleAiRequest(prompt);
}}
```

4. **initSocket token 获取失败日志**：
```typescript
if (!token) {
  console.error('[ChatSocket] No token available, socket not created');
  return;
}
```

**文件**：
- `apps/desktop/src/renderer/hooks/useChatSocket.ts`（4 处修改）
- `apps/desktop/src/renderer/components/chat/MessageInput.tsx`

## 问题 2：Mobile AI 按钮返回不相关建议

**阶段**：手动测试 — Mobile 端 Whisper AI 建议

**现象**：
1. 输入 `帮我解释微信小程序@ai` 按发送 → 建议与"微信小程序"相关（**正确**，`@ai` 路径有效）
2. 在输入框输入 `帮我解释小程序` 后点击 AI ✨ 按钮 → 建议返回"你好，有什么可以帮你的吗？"等通用内容（**不相关**）

**原因**：两条触发路径的 prompt 传递不一致：

| 触发方式 | prompt 值 | 效果 |
|---------|----------|------|
| `@ai` 发送拦截 | `"帮我解释微信小程序"` | LLM 结合用户请求生成建议 ✅ |
| AI 按钮点击 | `null` | LLM 仅根据聊天历史生成建议 ❌ |

`@ai` 路径在 `_handleSend()` 中提取了用户文本（去除 `@ai`）作为 prompt 传递给服务端。但 AI 按钮直接调用 `widget.onAiButtonPressed?.call(null)`，完全忽略了输入框中的文本。

此问题同时存在于 Desktop 端（但因问题 1 的 socket 断连，Desktop 未能测试到此阶段）。

**修复**（双端）：

**Mobile `message_input.dart`**：AI 按钮点击时提取输入框文本作为 prompt：
```dart
// Before
onPressed: widget.aiLoading ? null : () => widget.onAiButtonPressed?.call(null),

// After
onPressed: widget.aiLoading ? null : () {
  final inputText = _controller.text.trim();
  final prompt = inputText.isNotEmpty
      ? inputText.replaceAll(_aiPattern, '').trim()
      : null;
  widget.onAiButtonPressed?.call(prompt?.isNotEmpty == true ? prompt : null);
},
```

**Desktop `MessageInput.tsx`**：已在问题 1 修复中一并处理（onClick 箭头函数提取 `text.trim()` 作为 prompt）。

**文件**：
- `apps/mobile/lib/features/chat/widgets/message_input.dart`
- `apps/desktop/src/renderer/components/chat/MessageInput.tsx`（同问题 1）

## 问题 3：Whisper 建议与用户请求完全无关（服务端 prompt 未传递到 LLM）

**阶段**：代码审计 — 追踪 prompt 传递链

**现象**：即使客户端正确传递了 prompt，服务端 LLM 调用仍然忽略用户的请求文本，只使用聊天历史生成建议。

**原因**：prompt 传递链在服务端断裂。`handleWhisperRequest` 接受了 `prompt` 参数并传给 `generateSuggestions`，但 `generateSuggestions` 方法签名只接受 `context: string`，不接受 prompt：

```typescript
// handleWhisperRequest 传了 prompt
const suggestions = await this.generateSuggestions(context, prompt);

// 但 generateSuggestions 签名只有 context
async generateSuggestions(context: string): Promise<WhisperSuggestions | null> {
  // prompt 被 TypeScript 静默丢弃（多余的位置参数）
  // LLM 调用中完全没有 prompt 的痕迹
  const response = await this.llmRouter.complete({
    messages: [{
      content: `以下是聊天记录:\n\n${context}\n\n请根据上下文生成 3 条回复建议。`
    }],
    ...
  });
}
```

此外，整条 prompt 传递链涉及 6 层调用，其中多处遗漏：

| 层级 | 文件 | 状态 |
|------|------|------|
| 1. 客户端输入提取 | Desktop `MessageInput.tsx` / Mobile `message_input.dart` | ❌ AI 按钮未提取 |
| 2. Socket emit | Desktop `useChatSocket.ts` / Mobile `chat_socket_service.dart` | Desktop ✅ / Mobile ❌ |
| 3. WS 协议类型 | `ws-protocol/ai.payloads.ts` | ✅ 已有 `prompt` 字段 |
| 4. Gateway 解析 | `chat.gateway.ts` | ✅ 传递 `data.prompt` |
| 5. Service 方法 | `whisper.service.ts` `handleWhisperRequest` | ✅ 接受 prompt |
| 6. LLM 调用 | `whisper.service.ts` `generateSuggestions` | ❌ 签名缺 prompt |
| 7. Provider 传递 | Mobile `whisper_provider.dart` | ❌ 缺 prompt 参数 |

**修复**（全链路，7 个文件）：

1. **`whisper.service.ts`** — `generateSuggestions` 新增 `prompt?: string` 参数，有 prompt 时 LLM 消息包含"用户的请求"：
```typescript
async generateSuggestions(context: string, prompt?: string) {
  let userContent = `以下是聊天记录:\n\n${context}\n\n`;
  if (prompt) {
    userContent += `用户的请求: ${prompt}\n\n请根据聊天上下文和用户的请求生成 3 条回复建议。`;
  } else {
    userContent += `请根据上下文生成 3 条回复建议。`;
  }
  // ...
}
```

2. **Mobile `chat_socket_service.dart`** — `emitWhisperRequest` 新增 `{String? prompt}` 命名参数
3. **Mobile `whisper_provider.dart`** — `requestSuggestions` 新增 `{String? prompt}` 命名参数
4. **Mobile `message_input.dart`** — `onAiButtonPressed` 回调从 `VoidCallback?` 改为 `Function(String?)?`，`_handleSend` 中 @ai 拦截提取 prompt
5. **Mobile `chat_thread_page.dart`** — `onAiButtonPressed: (prompt) { ... requestSuggestions(prompt: prompt) }`
6. **Desktop `useChatSocket.ts`** — `emitWhisperRequest` 已支持 prompt（前次实现）
7. **`whisper.service.spec.ts`** — 新增测试用例验证 prompt 传递到 LLM

**文件**：
- `apps/server/src/ai/services/whisper.service.ts`
- `apps/server/src/ai/services/whisper.service.spec.ts`（新增 1 个测试）
- `apps/mobile/lib/core/network/chat_socket_service.dart`

### 问题 4：Desktop 请求被确认但建议未返回

**阶段**：修复验证 — Desktop 端 AI 按钮

**现象**：
1. Socket 已连通（修复生效 ✅）：`socket connected: true`
2. 请求发送成功：`whisper request ack: { success: true }`
3. 但 5 秒后超时，建议从未到达客户端

**Console 日志**：
```
[AI] handleAiRequest called, converseId: cmmiv539c000lgdz8rv0ut8xd prompt: 什么是大模型
[AI] emitWhisperRequest, socket connected: true converseId: cmmiv539c000lgdz8rv0ut8xd prompt: 什么是大模型
[AI] whisper request ack: {success: true}
[AI] 5s timeout — loading reset
```

**分析**：
- 服务端 Gateway 采用 fire-and-forget 模式：收到请求立即返回 `{success: true}`，异步调用 `handleWhisperRequest`
- `handleWhisperRequest` → `generateSuggestions` → `llmRouter.complete()` 中的 LLM 调用可能失败
- **关键问题**：`generateSuggestions` 的 catch 块是**完全静默的**（`catch { return null; }`），不记录任何错误信息
- 当 LLM 调用失败时，`handleWhisperRequest` 收到 null，仅记录 "timed out" 警告后返回，从未广播建议

**修复**：

1. **`whisper.service.ts` — `generateSuggestions`**：移除无用的 AbortController，catch 块增加详细错误日志：
```typescript
catch (error) {
  const msg = error instanceof Error ? error.message : String(error);
  this.logger.error(`[generateSuggestions] LLM call failed: ${msg}`);
  return null;
}
```

2. **`whisper.service.ts` — `handleWhisperRequest`**：每步增加日志（context 提取 → LLM 调用 → DB 保存 → 广播）：
```typescript
this.logger.log(`[handleWhisperRequest] START userId=${userId}, converseId=${converseId}, prompt=${prompt}`);
// ... 每步 debug 日志 ...
this.logger.log(`[handleWhisperRequest] DONE — suggestions broadcast to u-${userId}`);
```

3. **Desktop `useChatSocket.ts` — `ai:whisper:suggestions` 监听器**：增加 `console.log` 以确认事件是否到达客户端：
```typescript
socket.on('ai:whisper:suggestions', (data) => {
  console.log('[AI] Received whisper suggestions:', data.suggestionId, 'primary:', data.primary?.substring(0, 50));
  // ...
});
```

**根因待确认**：需要重启服务端后观察 NestJS 日志中的 `[handleWhisperRequest]` 和 `[generateSuggestions]` 输出。最可能的原因是 LLM API 调用失败（API Key 缺失或无效）。

### 问题 5：Mobile @ai 拦截路径失效

**阶段**：修复验证 — Mobile 端 @ai 发送

**现象**：
1. AI 按钮**正常工作**（Round 1 修复生效 ✅）
2. @ai 发送路径**不工作**

**分析**：
- AI 按钮和 @ai 发送**使用相同的回调链**：`widget.onAiButtonPressed?.call(prompt)` → `requestSuggestions(prompt: prompt)` → `emitWhisperRequest(converseId, prompt: prompt)`
- 代码逻辑上，两条路径都正确提取 prompt 并传递给同一个回调
- 最可能原因：**Flutter 热重载不完整**，部分旧编译代码仍在运行。需要完全重启（`flutter run`）

**修复**：增加 `debugPrint` 以诊断：
```dart
// @ai 拦截路径
debugPrint('[MessageInput] @ai intercept: text="$text", prompt="$prompt"');

// AI 按钮路径
debugPrint('[MessageInput] AI button: inputText="$inputText", prompt="$prompt"');
```

### 问题 6：Mobile 建议显示为原始 JSON 字符串

**阶段**：修复验证 — Mobile 端 Whisper 建议显示

**现象**：
1. Desktop 端 AI 功能**已恢复正常** ✅
2. Mobile 端 AI 按钮返回建议，但 WhisperBar 显示完整 JSON 字符串而非解析后的文本：
```
{"primary":"不止数据大，参数规模也大，动辄百亿千亿。","alternatives":["对，训练数据跟参数量都是巨量级。","","能大到啥程度？参数比数据更惊人，想深挖吗？"]}
```

**原因**：LLM（DeepSeek）将 JSON 包裹在 markdown 代码块中返回：
````
```json
{"primary":"...","alternatives":["..."]}
```
````
服务端 `parseSuggestions` 方法直接 `JSON.parse(content)` 失败（因 ````json` 前缀），回退到逐行解析，将整个 JSON 行作为 `primary` 返回。

此外，LLM 在 alternatives 中返回了空字符串 `""`，造成空白备选建议。

**修复**：

`whisper.service.ts` — `parseSuggestions` 新增 markdown 代码块剥离 + 空 alternatives 过滤：
```typescript
parseSuggestions(content: string): WhisperSuggestions {
  // Strip markdown code block wrapper if present (```json ... ```)
  let cleaned = content.trim();
  if (cleaned.startsWith('```')) {
    cleaned = cleaned
      .replace(/^```(?:json)?\s*\n?/, '')
      .replace(/\n?```\s*$/, '')
      .trim();
  }

  try {
    const parsed = JSON.parse(cleaned);
    if (parsed.primary && Array.isArray(parsed.alternatives)) {
      return {
        primary: String(parsed.primary),
        alternatives: parsed.alternatives
          .map(String)
          .filter((s: string) => s.length > 0)  // 过滤空字符串
          .slice(0, 2),
      };
    }
  } catch { /* ... */ }
  // ...
}
```

**文件**：
- `apps/server/src/ai/services/whisper.service.ts`
- `apps/server/src/ai/services/whisper.service.spec.ts`（新增 2 个测试：markdown 剥离 + 空 alternatives 过滤）

### 问题 7：Mobile 点击建议无法填入输入栏

**阶段**：修复验证 — Mobile 端建议采纳

**现象**：
1. WhisperBar 显示建议后，点击建议 chip 无反应，文本未填入输入栏

**原因**：`MessageInputState.prefillText()` 方法有一个输入非空守卫：
```dart
void prefillText(String text) {
  if (_controller.text.trim().isNotEmpty) return;  // ← 输入非空时拒绝填入
  _controller.text = text;
  // ...
}
```

用户流程：输入 `什么是大模型` → 点击 AI 按钮 → 建议到达 → 点击建议 chip → `prefillText` 检测到输入框仍有文本 → **静默拒绝**。

AI 按钮路径不会清空输入框（与 `@ai` 拦截路径不同，后者在 `_handleSend` 中调用 `_controller.clear()`）。因此用户输入的文本仍在，导致 prefillText 被守卫拒绝。

Desktop 端不受此问题影响——Desktop 的 prefillText 通过 `setText(prefillText)` 实现，没有非空守卫。

**修复**：

`message_input.dart` — 移除非空守卫。用户点击建议 chip 是明确的主动操作，应始终覆盖：
```dart
// Before
void prefillText(String text) {
  if (_controller.text.trim().isNotEmpty) return;  // 守卫
  _controller.text = text;
  // ...
}

// After
void prefillText(String text) {
  _controller.text = text;  // 始终覆盖
  _controller.selection = TextSelection.fromPosition(
    TextPosition(offset: text.length),
  );
  _focusNode.requestFocus();
}
```

**文件**：
- `apps/mobile/lib/features/chat/widgets/message_input.dart`
