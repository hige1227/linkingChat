### A3. 遇到的构建问题及修复

| 问题 | 原因 | 修复 |
|------|------|------|
| `node_modules` 未被打包 | electron-builder 默认忽略 `node_modules`，即使 `extraResources` filter 为 `**/*` | 在 `electron-builder.yaml` 显式添加 `from: sidecar/${os}-${arch}/node_modules` 条目 |
| `sidecarPath` 配置错误 | `openclaw-sidecar/cli.js` → 实际应为 `openclaw-sidecar/node_modules/openclaw/openclaw.mjs` | 修改 `openclaw.config.ts` 的 `sidecarPath` |
| `nodePath` 使用系统 node | 返回 `'node'` 而非 bundled `node.exe` | 新增 `nodeExePath` 配置，优先用 bundled node.exe |
| sidecar 591MB 过大 | npm install 包含 dev 依赖 + 平台特定二进制 | `--omit=dev` + filter 排除非 win-x64 prebuilds |

## B. 生产环境连接测试

### B1. 服务器更新

| 操作 | 结果 | 备注 |
|------|------|------|
| Server CORS_ORIGINS 配置 | ✅ | 添加 `CORS_ORIGINS=https://linkchat-api.matrix-ai.com.cn,http://localhost:3008` |
| Server 重启 | ✅ | `docker compose -f docker-compose.prod.yaml restart server` |
| HTTPS health check | ✅ | `https://linkchat-api.matrix-ai.com.cn/api/v1/health` → 200 |

**关键发现:** 生产环境 Socket.IO CORS 默认为空数组 `[]`，拒绝所有 WebSocket 连接。必须设置 `CORS_ORIGINS` 环境变量。

### B3. Agent 类型问题

| 测试项 | 结果 | 备注 |
|------|------|------|
| `getAgentType()` 返回 `'hermes'` | ⚠️ | 之前切换过，packaged app 保留了 electron-store 中的设置 |
| 切回 openclaw 后连接 | ✅ | `setAgentType('openclaw')` → 第二个点变绿 |

**教训:** Agent 类型持久化在 electron-store 中，打包版会继承开发环境的设置。需要在新安装时重置为默认值。

| 测试项 | 结果 | 备注 |

### C3. 结论

**Sidecar OpenClaw 的 LLM 调用超时，全局 OpenClaw 正常。** 原因待查（可能是 bundled node.exe 的网络层或 bundled openclaw 包的依赖问题）。

**解决方案:** 按计划文档 (`docs/superpowers/plans/2026-04-19-server-llm-proxy.md`)，LLM 调用将走 Server AI Gateway 代理，sidecar OpenClaw 仅负责本地工具执行。此问题在 Server 代理上线后自动消失。
